# 「麦门订单管家」界面规范 v2

## 一、视觉方向

v2 把界面从「纸质收纳夹」调整为**麦当劳 App 式的暖色工具界面**：红黄品牌色、24px 大圆角、
粗体大数字、卡片式列表、底部导航。目标是让用户第一眼有熟悉的观感，但**不冒充官方产品**。

### 品牌边界（硬约束）

| 做 | 不做 |
|---|---|
| 使用麦当劳常见的红（#DA291C）与黄（#FFC72C）作为主色 | **不绘制金拱门 Logo**，不使用任何麦当劳商标图形 |
| 使用本项目自有标识（票券 logo）作为应用图标 | 不把自有标识做成与官方标识近似的样子 |
| 借用 App 的信息结构：顶栏、Hero 卡、看板、底部 Tab | 不复制官方 App 的具体页面布局、图标或产品图 |
| 页头 + 页脚固定「个人效率工具 · 非麦当劳官方产品」 | 不在任何位置暗示与麦当劳存在合作或授权关系 |

> 票券 logo 是本项目自有标识（红票券 + M + 星芒 + 三色圆点），**不是**金拱门商标，
> 也不代表任何授权。加入 logo 不改变「非官方」声明的位置与强度。

这条边界与交付稿第 9.2 节「不模拟官方 App 的视觉身份」是一致的：**借用色彩语言与结构习惯，
不借用品牌标识与身份**。身份声明必须比品牌感更显眼地存在。

## 三、字体

- 字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans SC", "Microsoft YaHei"`
- 数字：`"SF Mono", "IBM Plex Mono", Consolas` + `font-variant-numeric: tabular-nums`
- 层级：品牌标题 17/800、Hero 数字 46–54/800、卡片数字 30–32/800、列表标题 15/700、
  辅助 12/600、金额 19–20/800
- 负字距：大数字 `-1.2px ~ -2px`，标题 `-0.3px`，营造 App 的紧凑感

## 五、模块卡的五种状态

用「图标底色 + 右上角徽标 + 边框/底色」三重表达，不只靠颜色：

| 状态 | 图标底色 | 右上徽标 | 按钮 |
|---|---|---|---|
| 待处理 | 浅红 | 红底白字「待处理」 | 红色实心 |
| 可参与（需确认） | 浅黄 | 黄底深字「可参与」 | 黄色实心 |
| 已完成 | 浅绿 | 绿字「已清空」 | 浅红底红字 |
| 不可用 | 虚线框 | 「不可用」 | 虚线描边 |
| 数据过期 | — | 面板内红色提示条 | **只保留「重新查询」** |

## 六、列表行

- 左侧：门店名 15/700 + 元信息 12/600（时间 · 类型 · 状态）
- 右侧：金额 19/800 右对齐 + 状态标签
- 行高 ≥ 72px，行间 1px 实线分隔，首行无上边框
- 发票行整行可点，左侧 22px 勾选框（`accent-color: red`）
- 移动端自动换行：信息在上，金额与标签在下，**金额靠右**

## 七、移动端（≤ 760px）

- 顶栏常驻，底部导航常驻（4 项：看板 / 待评价 / 开票 / 抽奖），`env(safe-area-inset-bottom)` 适配
- 内容底部留 96px，避免被导航遮挡
- 模块卡单列；分段标签隐藏，改由底部导航切换
- 按钮最小 46px 高、44px 触控区
- 无横向滚动；Hero 统计胶囊在移动端隐藏（信息已在卡片中）

## 八、兑礼进度与报销门槛

两个新增组件，解决「还差多少」这类聚合问题：

| 组件 | 位置 | 样式 | 行为 |
|---|---|---|---|
| 兑礼进度 `.reward` | 待评价候选卡头部下方 | ★ 图标 + 13px 粗体文案 + 11px 门店规则说明 | 只读，展示「已达成 / 还差几单」 |
| 报销门槛 `.chips` `.chipbtn` | 开票清单，候选卡与资料卡之间 | 36px 圆角胶囊，选中红底白字 | 点击后自动勾选最少凑单组合，合计同步刷新 |
| 已评标记 `.markbtn` | 待评价列表每行右侧 | 30px 胶囊按钮，默认灰字，标记后变绿字「撤销」 | 点击写入本机 localStorage，行淡出并隐藏，计数与兑礼进度同步 |

规则：

- 门槛默认提供 `¥50` / `¥100` 两档，由快照数据决定，不在前端算钱（前端只做勾选联动）。
- 凑不够时按钮仍可点，文案改为「还差 ¥xx」且**不勾选任何订单**。
- 支持 `?target=100` 深链直接进入已勾选状态，便于演示与分享。
- 兑礼档位可配置，界面只显示文案，不在前端硬编码档位数字。
- **已评标记只存订单号哈希**（`mm.reviewed.v1`，FNV-1a），不存订单原文、不上传、不写服务端。
- 接口不返回评价状态，所以界面对这类订单一律显示「待确认」，**不显示「未评价」**；
  该提示固定在列表下方，用户随时能看到依据。

## 九、可访问性

- `:focus-visible` 3px 红描边，offset 3px；分段标签支持 ←/→ 切换
- 状态不只用颜色：都带文字徽标
- 正文对比：`#1F1B16` on `#FFF8EE` ≈ 15:1；按钮白字 on `#DA291C` ≈ 5:1
- 支持 `prefers-reduced-motion`（关闭过渡与平滑滚动）
- 提示条 `role="status" aria-live="polite"`

## 十、文案

保留动作即结果的按钮词：`查看待评价订单`、`整理开票资料`、`查询抽奖活动`、`确认抽 1 次`、`打开官方 App`、`重新查询`。

禁用「收割」「薅羊毛」「一键搞定」「自动完成」。
「可能待评价」「无法确认」「推断」等限定词不得简写或省略。

## 十一、Logo 资源

| 资源 | 尺寸 | 用途 |
|---|---|---|
| `ui/assets/logo-512.png` | 512×512 透明 PNG | 高清/打印/分享图 |
| `ui/assets/logo-192.png` | 192×192 | 顶栏、页脚、apple-touch-icon |
| `ui/assets/logo-64.png` | 64×64 | 小图标位 |
| `ui/assets/favicon.ico` | 16/32/48/64 | 浏览器标签页 |

处理方式（`ui/assets/build_logo.py`，一次性脚本，需要 Pillow）：

1. 从四角**泛洪填充**只移除外部连通的白色背景，票券内部的奶油色完整保留；
2. alpha 腐蚀 1px + 轻微模糊，去掉 JPEG 边缘白边；
3. 按 alpha 边界裁剪，两侧补 6% 留白成正方形；
4. LANCZOS 缩放出多尺寸。

使用位置：顶栏 46×46、页脚 38×38，均 `object-fit: contain`。替换 logo 只需重跑脚本，
无需改 HTML 之外的任何代码。

## 十二、与交付稿的偏差（有意为之）

| 项 | 交付稿 | 实现 | 原因 |
|---|---|---|---|
| 整体气质 | 「权益收纳夹」纸质感 | 麦当劳 App 式红黄界面 | 用户明确要求「更像麦当劳 App」；保留非官方声明与无 Logo 边界 |
| 主色 | `--tomato #C9362B` | `#DA291C`（麦当劳红） | 观感一致性，对比度达标 |
| 移动端正文字号 | 14px | 16px | 移动端可读性门槛（UX-033） |
| 首页统计 | 仅待处理总数 | 总数 + 三项胶囊 | 宽屏时填补右侧空白，并给出一眼可读的分项 |
| 抽奖确认 | 真实执行 | 预演 + 明确标注「未真实抽奖」 | 静态页不持有会话与 Token，真实执行在对话中完成 |
