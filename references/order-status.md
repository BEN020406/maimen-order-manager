# 订单状态映射与「待确认」判定

> **2026-10-21 实测结论：麦当劳 MCP 不返回任何评价状态。**
> `order-list` 与 `query-order` 都没有 `orderStatusCode`，也没有 review/comment/score 字段。
> 因此本技能的「待评价」不再由接口判定，而是：**列出已完成订单 → 标「待确认」→ 用户本地标记「已评过」**。
> 下图保留状态码分支，是为了将来接口若补充该字段时能自动生效。

## 一、判定顺序（不可颠倒）

```
1. status_code == "8"                → reviewed（已评价）
2. status_label 含「已评价/已评论」  → reviewed（已评价）
3. status_label 含 取消/关闭/退款    → not_eligible（不适用）
4. status_label 含 待支付/未支付     → not_eligible（不适用）
5. status_label 含 进行中/制作中/配送中/待取餐 → not_eligible（不适用）
6. status_label 含 已完成/已送达/已取餐：
     ├─ status_code 存在且 ≠ 8      → likely_pending（可能待评价）
     └─ status_code 缺失            → unknown（待确认）
7. 状态为空或无法识别                → unknown（待确认）
```

关键点：第 6 步走哪一支，取决于接口**有没有**评价字段。实测没有，所以现实里全部落在
`unknown`，界面显示「待确认」，再由用户本地标记「已评过」。这不是降级妥协，而是接口能力的边界。

## 二、状态码

| 码 | 含义 | 状态 |
|---|---|---|
| `8` | 交付稿约定的「已评价」 | **接口未返回该字段**，仅作兼容 |
| 其它数值 | 不做语义推断 | — |

状态码归一化：`8`、`"8"`、`8.0` 都视为 `"8"`。
`query-order` 里另有一个 `status`（实测值 40），是内部订单状态码、含义未公开，**不用于评价判定**。

## 三、文案关键词表

| 类别 | 关键词 |
|---|---|
| 已评价 | 已评价、已评论、已点评 |
| 不适用-取消 | 取消、关闭、已退款、退款、失败 |
| 不适用-未支付 | 待支付、未支付、待付款、支付中、待确认 |
| 不适用-进行中 | 进行中、制作中、待取餐、待取货、配送中、待接单、备餐、已下单、待发货 |
| 已完成 | 已完成、完成、已送达、已取餐、已收货、已消费 |

关键词匹配为「包含」语义，命中即返回，顺序以第一节为准。

## 四、统计口径

- 分母 = **接口本次实际返回的订单数**（`order-list` 通常 ≤ 10 笔）。
- 待评价候选 = `likely_pending` 数量。
- `reviewed` 不计入；`not_eligible` 不计入；`unknown` 单独说明，**也不计入**。
- 输出必须包含「统计范围：最近 N 笔订单」。禁止写「你所有未评价订单」。

示例：

```text
待评价候选：3 笔
统计范围：最近 10 笔订单

2026-10-20  麦当劳·上海徐家汇店  ¥42.00  可能待评价
2026-10-18  麦当劳·上海陆家嘴店  ¥31.50  可能待评价
2026-10-12  麦当劳·上海陆家嘴店  ¥42.00  可能待评价

另有 1 笔订单无法确认评价状态（接口未返回评价字段），未计入待评价。
另有 3 笔未完成或已取消订单未纳入统计。
```

## 五、城市字段的推断规则

订单接口没有城市字段，只有 `storeName`（如「麦当劳·上海南京东路店」）。

| 情况 | `city_source` | 展示 |
|---|---|---|
| 接口返回了城市字段 | `field` | 直接使用，不作额外标注 |
| 仅门店名可匹配城市名 | `store_name` | 使用，但必须标注「推断，非接口字段」 |
| 都不满足 | `unknown` | 显示「未知」，**按城市筛选时排除**，不做猜测归类 |

推断只做「常见城市名是否为门店名子串」的匹配，不解析行政区划、不使用外部地理库。

## 六、展示字段

单条订单至少展示：日期、门店、实付金额、状态标签。用户追问时再补订单类型、
商品明细、订单号（脱敏）。订单类型为数字码时如实写「类型码 N（接口未定义）」。

## 七、官方 App 路径

```text
麦当劳官方 App → 我的 → 订单 → 选择该订单 → 评价
```

只给路径，不代提交，不生成虚假评价文本。
