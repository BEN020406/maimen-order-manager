# 发票助手：筛选、校验与交接

## 一、边界

- 只筛选**真实存在**的订单，金额/门店/城市/日期全部来自订单返回值。
- **不提交发票**：`issue-invoice` 未在公开工具列表；即使将来出现，按策略仍由用户本人在官方 App 提交。
- 不修改订单金额、门店、城市，不拼接、不拆单、不合并开票。
- 税号与邮箱只在当前会话内存中使用，输出一律脱敏，不写磁盘。

## 二、候选筛选规则

| 条件 | 规则 |
|---|---|
| 状态 | 必须为「已支付」或「已完成」，且不含取消/关闭/退款 |
| 城市 | 优先接口字段；缺失时用门店名推断并标注「推断」；两者都无 → 排除并说明 |
| 门店 | `storeName` 包含匹配 |
| 日期 | 按 `createTime` 闭区间过滤 |
| 金额 | 按实付金额过滤；**金额未知的订单不参与上下限筛选**，且不计入合计 |

合计口径：

```
total = Σ 候选订单 paid_amount（Decimal 两位小数）
若存在金额缺失的订单 → 单独提示「合计不含这些订单」
```

## 三、开票资料校验

| 字段 | 必填 | 规则 | 不通过时 |
|---|---|---|---|
| 公司抬头 | 是 | 去空格后非空 | 阻断出清单，提示补全 |
| 统一社会信用代码 | 是 | 18 位；字符集 `0-9 A-H J-N P Q R T U W X Y`（不含 I/O/S/V/Z）；GB 32100-2015 校验位 | **不阻断**，提示「请人工检查」 |
| 接收邮箱 | 否 | 基础格式 `xx@yy.zz` | 格式异常时提示，不阻断 |

校验位算法：

```
weights = [1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28]
check = 31 - (Σ charset_index(char_i) * weights[i]) % 31
check == 31 → 0
末位应等于 charset[check]
```

真实编码可用于自测：`91350100M000100Y43`、`9131000063116937XG` 均应通过。

## 四、脱敏

| 类型 | 规则 | 示例 |
|---|---|---|
| 税号 | 前 4 + `*`×(len-8) + 后 4 | `9135**********0Y43` |
| 邮箱 | 首字母 + `***@域名` | `f***@example.com` |
| 订单号 | 前 3 + `*` + 后 3 | `DD2*******001` |
| Token | 前 4 + `********` | `abcd********` |

日志、错误回传、示例文件、界面一律只出现脱敏值。**测试会断言税号原文不出现在输出中。**

## 六、交接话术要点

1. 先给数字（几笔、合计多少），再给清单，最后给路径。
2. 明确说「我没有替你提交」，避免用户以为已经开好了。
3. 城市是推断出来的要主动说明，别让用户拿着错城市去开票。
4. 税号校验失败时，说明「校验位不匹配」而不是「税号错误」——可能只是特殊编码。
5. 用户要求「直接开好」时，回答：本技能只整理清单，提交必须本人在官方 App 完成。

## 七、常见追问

| 追问 | 回答要点 |
|---|---|
| 为什么只有最近几笔？ | `order-list` 只返回最近订单，只承诺接口实际范围 |
| 为什么有的订单不在列表里？ | 状态不是已支付/已完成，或城市字段缺失被排除（会说明原因） |
| 能不能合并开一张？ | 官方 App 的规则决定，本工具不合并、不拆单 |
| 金额为什么和订单页不一致？ | 一律以订单实付金额为准，差异请核对官方 App |
